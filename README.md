# Advandex — предсказание вероятности клика по рекламному объявлению

## О проекте

Проект посвящён прогнозированию вероятности того, что пользователь кликнет по рекламному объявлению на платформе рекламного аукциона.

Задача сформулирована как **бинарная классификация**: модель получает информацию о пользователе, устройстве, сайте, приложении и характеристиках рекламного показа и предсказывает вероятность клика.

Основная цель — построить модель, которая не только хорошо разделяет пользователей на кликнувших и не кликнувших, но и выдаёт **корректно интерпретируемые вероятности**.

---

## Бизнес-задача

Для рекламной платформы важно оценивать вероятность клика пользователя по каждому рекламному показу.

Полученные вероятности могут использоваться для:

* ранжирования рекламных объявлений;
* оптимизации рекламного аукциона;
* оценки эффективности рекламных показов;
* прогнозирования CTR;
* принятия решений на основе ожидаемой вероятности клика.

В отличие от простой классификации, в проекте отдельно рассматривается **калибровка вероятностей**, поскольку значение `0.7` должно означать примерно 70% вероятности события для соответствующей группы наблюдений.

---

## Данные

В датасете представлены 50 000 рекламных показов и 34 исходных признака.

Целевая переменная:

* `click` — факт клика по рекламному объявлению:

  * `0` — клика не было;
  * `1` — был клик.

Доля положительного класса составляет около **17.2%**, поэтому классы несбалансированы.

Среди признаков присутствуют:

* характеристики сайта;
* характеристики приложения;
* информация об устройстве;
* категории сайтов и приложений;
* технические характеристики рекламного показа;
* ML-признаки;
* временной признак `hour`.

Технический идентификатор `id` был исключён из моделирования.

---

## Исследовательский анализ данных

На этапе EDA были изучены:

* распределения числовых признаков;
* кардинальность категориальных признаков;
* корреляции числовых признаков с целевой переменной;
* зависимости между категориальными признаками;
* выбросы;
* потенциально избыточные признаки.

Для анализа взаимосвязей категориальных признаков использовался коэффициент **Cramér's V**.

Были обнаружены сильные зависимости между некоторыми признаками, например:

* `site_id` и `site_domain`;
* `site_id` и `site_category`;
* `app_id` и `app_domain`;
* `app_id` и `app_category`.

Это указывает на наличие существенной избыточности в части категориальных признаков.

---

## Предобработка данных

Для числовых признаков использовались:

* заполнение пропусков медианой;
* ограничение экстремальных значений по квантилям;
* стандартизация с помощью `StandardScaler`.

Для категориальных признаков применялось два подхода.

### One-Hot Encoding

Для признаков с небольшой кардинальностью использовался `OneHotEncoder`.

В эту группу вошли:

* `site_category`;
* `app_category`;
* `ml_feature_2`;
* `ml_feature_7`.

### Target Encoding

Для категориальных признаков с высокой кардинальностью применялся `TargetEncoder`.

Это позволило избежать огромного количества бинарных признаков при работе с такими полями, как:

* `device_ip`;
* `device_id`;
* `device_model`;
* `site_id`;
* `site_domain`;
* `app_id`;
* `app_domain`.

Target Encoding обучался только на тренировочной выборке, чтобы избежать утечки информации из целевой переменной.

---

## Отбор признаков

Для сокращения размерности и удаления маловариативных признаков сравнивались два подхода:

* `VarianceThreshold`;
* `RFE`.

В качестве основной метрики использовался **PR-AUC (Average Precision)**, поскольку положительный класс составляет только около 17% наблюдений.

Результаты:

| Метод             | Количество признаков | Mean PR-AUC |
| ----------------- | -------------------: | ----------: |
| VarianceThreshold |                   21 |      0.3672 |
| RFE               |                   25 |      0.3652 |

В качестве основного метода был выбран `VarianceThreshold`: он дал немного более высокий средний PR-AUC и позволил использовать меньше признаков.

---

## Обучение моделей

В качестве базовой модели использовался `DummyClassifier`.

Средний PR-AUC базовой модели составил около **0.172**, что соответствует доле положительного класса.

После этого сравнивались:

* Logistic Regression;
* Linear SVC.

Результаты показали преимущество Logistic Regression по PR-AUC.

Для дальнейшей оптимизации использовался `GridSearchCV` с подбором:

* коэффициента регуляризации `C`;
* максимального количества итераций `max_iter`.

В качестве основной метрики оптимизации использовался **PR-AUC**.

---

## Финальная модель

В качестве финальной модели была выбрана **Logistic Regression**.

Модель использует 21 отобранный признак.

На кросс-валидации были получены следующие результаты:

| Метрика     | Среднее значение |
| ----------- | ---------------: |
| PR-AUC      |       **0.4087** |
| Brier Score |       **0.1233** |
| Precision   |       **0.6208** |
| Recall      |       **0.1162** |
| F1          |       **0.1958** |

PR-AUC вырос относительно baseline примерно с **0.172 до 0.409**, что показывает существенное улучшение способности модели выделять пользователей с большей вероятностью клика.

При стандартном пороге 0.5 модель имеет относительно высокую precision, но низкий recall. Поэтому для практического применения порог классификации может подбираться отдельно в зависимости от бизнес-задачи.

---

## Калибровка вероятностей

Отдельное внимание уделено качеству предсказанных вероятностей.

Для оценки калибровки использовались:

* **Brier Score**;
* **ECE (Expected Calibration Error)**;
* **MCE (Maximum Calibration Error)**.

Были рассмотрены два метода:

* Isotonic Regression;
* Platt Scaling / Sigmoid Calibration.

### Сравнение

| Модель               | Brier Score |    ECE |    MCE |
| -------------------- | ----------: | -----: | -----: |
| Logistic Regression  |      0.1293 | 0.0058 | 0.1797 |
| Isotonic Calibration |      0.1297 | 0.0153 | 0.0636 |
| Platt Scaling        |      0.1293 | 0.0074 | 0.1743 |

Изотоническая калибровка существенно уменьшила максимальную ошибку калибровки MCE, однако при этом увеличила ECE и немного ухудшила Brier Score.

Platt Scaling практически сохранил Brier Score, но не дал заметного улучшения остальных показателей.

Таким образом, калибровка не дала однозначного улучшения всех метрик одновременно. Для финального артефакта использовалась модель с изотонической калибровкой.

## Результат

В рамках проекта построен полный pipeline бинарной классификации:

**EDA → preprocessing → encoding → feature selection → model selection → cross-validation → probability calibration → сохранение модели → проверка воспроизводимости.**

Финальная модель позволяет получать вероятность клика по рекламному показу и может служить основой для дальнейшей оптимизации рекламного аукциона и принятия решений на основе прогнозируемого CTR.
